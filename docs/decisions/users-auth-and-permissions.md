| IAM-014 | 2026-09-18 | DECIDED | 시스템 관리자만 사용자를 조회·생성하며 생성 시 일반 사용자 또는 시스템 관리자 역할과 소속 조직을 지정한다. 신규 계정은 활성·비밀번호 변경 필요 상태로 시작한다. 선택 이메일은 공백 제거·소문자 정규화 후 고유하게 저장하고 빈 값은 NULL로 둔다. | 기존 인증 서비스의 ID·비밀번호 정책과 첫 로그인 변경 흐름을 재사용한다. 목록 DTO와 오류 화면에 비밀번호·hash를 포함하지 않는다. 이메일은 기본 주소 형식만 검사하며 소유권 확인·메일 발송은 하지 않는다. |
| IAM-015 | 2026-09-23 | DECIDED | 프로젝트 역할과 저장 code를 프로젝트 게스트(`PROJECT_GUEST`)·프로젝트 사용자(`PROJECT_USER`)·프로젝트 관리자(`PROJECT_ADMIN`)로 통일한다. 게스트는 프로젝트 업무 데이터를 읽기만 하고 담당자가 될 수 없다. 사용자는 creator·assignee와 무관하게 모든 티켓과 티켓 종속 콘텐츠를 생성·수정·상태 전이·휴지통 이동·복구하며, 관리자는 이에 더해 프로젝트와 참여자·역할을 관리한다. 시스템 관리자는 사용자·조직·전체 프로젝트와 보존·정리 작업을 관리한다. 자동 작업은 별도 사용자 역할이 아닌 내부 system actor로 기록한다. | 작은 사내 협업 도구에서 티켓별 소유권 권한을 제거해 역할 판정을 단순화한다. 프로젝트 격리, FSM, 종료 티켓 잠금, optimistic locking과 감사·이력은 별도 안전 규칙으로 유지하며 자동 실행과 관리자 수동 실행은 로그에서 구분한다. |

## Open decisions

- reverse proxy 환경에서 신뢰할 proxy 주소와 실제 client IP 전달 정책은 배포 환경이 정해질 때 확정한다.

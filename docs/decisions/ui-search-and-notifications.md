# UI, search, and notification decisions

| ID | 날짜 | 상태 | 결정 | 근거·영향 |
|---|---|---|---|---|
| UI-001 | 2026-09-16 | DECIDED | 초기 MVP 검색은 접근 가능한 티켓의 키와 제목만 대상으로 대소문자를 구분하지 않는 단순 검색을 제공한다. | 전문 검색 인프라 없이 자주 쓰는 탐색을 제공한다. 설명·댓글 한국어 전문 검색은 후속 범위다. |
| UI-002 | 2026-09-16 | DECIDED | 저장 필터는 허용된 필드·연산자·값·정렬·페이지 크기의 versioned JSON으로 저장하며 JQL 같은 실행형 사용자 query 언어는 제공하지 않는다. | 입력을 SQL이나 코드로 해석하지 않고 기존 typed filter DTO로 검증할 수 있다. |
| UI-003 | 2026-09-16 | DECIDED | 목록 페이지 크기는 10·20·50만 허용하고 기본값은 20이며 항상 안정적인 보조 정렬을 적용한다. | 페이지 이동 중 중복·누락을 줄이고 임의의 과도한 조회를 막는다. |
| UI-004 | 2026-09-16 | DECIDED | 칸반은 프로젝트별 상태 열과 Epic group을 사용하고 Task·Subtask가 다른 상태일 때 Subtask를 자신의 상태 열에 표시한다. | 실제 상태를 숨기지 않으면서 부모 업무를 식별할 수 있게 한다. |
| UI-005 | 2026-09-16 | DECIDED | 대시보드와 멘션은 페이지 진입 및 수동 새로고침으로 갱신하며 MVP에 email, realtime push, toast를 포함하지 않는다. | 초기 범위에서 메시징 인프라와 전달 실패 정책을 제외한다. |
| UI-006 | 2026-09-16 | DECIDED | 회사 정책에 따라 모바일 화면과 모바일 최적화는 지원하지 않고 초기 범위에서 dark mode도 제외한다. 색상은 향후 변경을 위해 design token으로 관리한다. | 데스크톱 사내 업무 흐름에 집중하면서 테마 추가 비용은 낮춘다. |

## Open decisions

- 목록의 인라인 상세 패널을 server-rendered partial, HTMX, 또는 별도 client state 중 무엇으로 구현할지는 UI 기반 작업 전에 확정한다.
- 칸반 drag-and-drop library 선택은 접근성과 optimistic locking 처리 방식을 함께 검토하여 확정한다.

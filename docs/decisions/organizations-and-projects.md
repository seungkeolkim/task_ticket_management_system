# Organization and project decisions

| ORG-003 | 2026-09-16 | DECIDED | 조직 JSON import는 immutable organization key 기준의 추가·명시적 갱신만 허용하며 적용 전 preview 후 하나의 transaction으로 반영한다. | 기존 조직 전체 교체와 ID 변경으로 사용자 연결이 손실되는 것을 방지한다. JSON에 없다는 이유로 기존 조직을 삭제하지 않는다. |
| ORG-004 | 2026-09-18 | DECIDED | 조직 생성 시 서버가 UUID 문자열 key를 발급하고 이름을 trim한다. 같은 부모 아래 이름은 대소문자를 구분해 중복을 거부하며 최상위도 같은 규칙을 적용한다. | 기존 unique 제약과 일치하며 사용자 입력으로 안정 식별 키를 변경하거나 재사용하지 않는다. |
| ORG-005 | 2026-09-18 | DECIDED | 신규 조직의 부모와 신규 사용자의 소속은 해당 조직부터 최상위까지 모두 활성인 경우만 허용한다. 목록은 비활성 조직도 보여주며 직속 사용자 수는 활성 여부와 무관하게 집계한다. | 서버 검증으로 disabled 선택지 우회를 막는다. 조직 비활성화 자체와 기존 사용자 로그인에 미치는 영향은 후속 결정이다. |

## Project

| ID | 날짜 | 상태 | 결정 | 근거·영향 |
|---|---|---|---|---|
| PRJ-001 | 2026-09-16 | DECIDED | 조직 소속은 프로젝트 접근 권한을 자동 부여하거나 회수하지 않으며 `ProjectMember`에 명시적으로 등록된 사용자만 접근한다. | 조직 개편과 프로젝트 참여 변경을 독립적으로 관리한다. 조직 단위 권한은 후속 기능으로 둔다. |
| PRJ-002 | 2026-09-16 | DECIDED | 모든 프로젝트 종속 조회는 데이터를 가져온 뒤 검사하기보다 repository query 자체에 project와 membership 조건을 포함한다. | 목록·검색·첨부파일·멘션 등 우회 경로에서 타 프로젝트 데이터 존재가 노출되는 것을 막는다. |
| PRJ-003 | 2026-09-17 | DECIDED | 프로젝트 키는 생성 후 변경하지 않으며 표시 티켓 키는 프로젝트 키와 번호로 생성해 저장한다. 프로젝트의 `next_ticket_number`를 삭제와 무관하게 유지한다. | 외부 링크와 보고서 근거 식별자를 안정적으로 유지하고 `MAX(ticket.number)+1`로 삭제된 번호를 재사용하지 않는다. 번호 발급의 원자성은 티켓 서비스에서 검증한다. |
| PRJ-004 | 2026-09-19 | DECIDED | 시스템 관리자만 프로젝트를 생성하며 활성 사용자 한 명을 최초 프로젝트 관리자로 반드시 지정한다. 생성자에게 참여 권한을 자동 부여하지 않고 프로젝트·최초 구성원·감사를 같은 transaction으로 저장한다. 키는 trim·대문자 정규화 후 영문자로 시작하는 영문·숫자 2~32자이며 생성 후 변경하지 않는다. | 관리자가 없는 신규 프로젝트를 막고 기존 고유 키·구성원 제약을 재사용한다. |
| PRJ-005 | 2026-09-19 | DECIDED | 내 프로젝트는 시스템 관리자도 명시적으로 참여한 프로젝트만 보여준다. 시스템 관리자는 전체 프로젝트 목록과 직접 접근에서 override할 수 있으며 실제 반환 프로젝트별로 list/read/manage 권한 사용을 감사 기록한다. 비참여 일반 사용자에게는 존재하지 않는 프로젝트와 같은 404를 반환한다. | 참여 목록과 운영 접근의 의미를 구분한다. 프로젝트 사용자로 참여한 시스템 관리자의 관리 동작도 override로 기록한다. 비활성 프로젝트는 조회할 수 있으나 구성원 추가는 차단한다. |
| PRJ-006 | 2026-09-19 | DECIDED | 프로젝트 관리자와 시스템 관리자만 미참여 활성 사용자를 프로젝트 관리자 또는 사용자로 추가한다. 후보 검색은 조직과 무관하게 ID·로그인 ID·표시 이름만 최대 50개 제공한다. 기존 구성원 역할 변경·제거와 프로젝트 수정·비활성화는 후속이다. | 조직 소속과 참여 권한을 분리하고 민감한 계정 정보 없이 등록 대상을 선택하게 한다. 후보 검색과 저장에서 권한·활성 여부·중복을 각각 검사한다. |
| PRJ-007 | 2026-09-23 | DECIDED | 비활성 프로젝트는 기존 권한으로 조회할 수 있지만 티켓 생성·업무 필드 편집·상태 전이와 신규 구성원 등록을 허용하지 않는다. | 비활성화를 읽기 전용 보존 상태로 취급하여 과거 업무와 이력을 유지하면서 추가 업무 변경을 막는다. |

## Open decisions

- 조직 비활성화가 소속 사용자 로그인 또는 프로젝트 참여에 미치는 영향은 조직 관리 구현 전에 확정한다.
